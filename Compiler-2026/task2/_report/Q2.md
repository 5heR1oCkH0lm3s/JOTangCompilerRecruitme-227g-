# TASK2 Q2

>`ir/`接受`lib/`生成的初始非 SSA IR，通过一系列优化 Pass 处理后，最终输出高质量的 .ll 优化目标文件。

其中：
>`ir/analysis`只读分析 IR 结构，计算支配树、支配边界与循环信息等数学属性，为后续变换提供前置数据支撑。其中的`Dominant`和`LoopInfo`也作为`AnalysisPass`在优化过程供`FAM`惰性调用。

---

## 1. Dominant

* 本项目项目采用的支配树算法是`Semi-NCA`，包含以下步骤：

1. **runDFS**: 对 CFG 进行深度优先遍历给每个可达的基本块打上时间戳编号(DFSNum)，同时记下每个块的所有前驱。
2. **runSemiNCA**: 先逆 DFS 序扫描,利用带路径压缩的并查集 (`compress/eval/link`)找到每个块绕过树边能达到的最早祖先（即半支配者`Sdom`）。再正 DFS 序回溯,顺着半支配者找到直接支配者`IDom`。
3. **buildDominatorTree**: 给所有节点连上父子指针，形成一棵树。

* GPT5.0编译器的源码使用的是`Lengauer-Tarjan Dominators Algorithm`。两者前半部分计算`Sdom`的原理完全一致，区别在于求`IDom`的过程。LT算法继续并查集和桶(`Bucket`)延迟机制，使其在理论上拥有接近线性的时间复杂度，但是这会使指针频繁跳跃，产生大量非连续的随机内存访问，导致CPU Cache极易失效。而Semi-NCA寻找最近公共祖先只在一个紧凑的整数数组（Infos）上单向寻址，内存极其连续，CPU缓存命中率高，实际效果快于理论更优的LT。

## 2. PHI

* PHI 函数是构建 SSA 形式的核心组件，通过在制流汇聚点显式合并变量的多个潜在赋值，将控制流带来的不确定性转化为了清晰、确定的数据流关联。在数据流优化中有以下作用：
  1. **统一 Use-Def 链**：变量一旦被转换为 SSA 形式并在分支汇合处引入 PHI 节点，每个变量在全局就具有唯一的定义。优化阶段只需沿着单向的 Use-Def（定义-使用）链条即可获知数据的来源和去向。
  2. **隔离局部作用域**： PHI 根据执行路径的来源（CFG 的前驱）动态选择最终传递的值。这种机制让各条分支上的数据更新互不干扰，从而支撑死代码消除、常量传播等优化。

* Phi 节点的插入算法基于**迭代支配边界（`Iterated Dominance Frontier`）**，其核心逻辑可以概括为以下四个步骤：
  1. **收集初始定义块**: 扫描目标 `Alloca` 变量的所有使用者，收集该变量发生 `Store` 操作的所有基本块集合（`DefBlocks`）。
  2. **反向计算活跃范围（Live-In）**： 从变量被 Load 且在此读取前本块未发生过赋值的位置开始，沿着 CFG 逆向传播，计算出该变量在哪些基本块入口是活跃的(`Live-In`)。
  3. **求迭代支配边界并裁剪**： 将收集到的 DefBlocks 作为根节点，在支配树上计算其支配边界(`Dom Frontier`)，并利用`Live-In`集合进行裁剪，得出 Phi 节点候选块。若这个刚刚插入 Phi 节点的基本块本身并不在`DefBlocks`中，会将其重新插入队列，继续计算 DF 迭代闭包。
  4. **插入 Phi 节点**： 遍历最终生成的候选边界块集合，在这些基本块的开头正式插入对应类型的 Phi 节点，作为后续变量重命名时的汇聚点。

>迭代支配边界确定`PHI`的汇聚点，`Live-In`集合裁剪不必要的`PHI`节点

## 3. Mem2Reg

* `Mem2Reg`（本项目里是 `PromotePass`）把入口块的标量 `alloca` 提升成 SSA，流程是**筛选 → 快速路径 → 插 PHI → 重命名 → 折叠退化 PHI**，整轮反复执行直到没有可提升对象。

* **筛选可提升对象**：只收"每个 use 都是类型匹配的直接 `load`/`store`"的非数组标量 `alloca`，其余视为逃逸跳过。

* **快速路径（不插 PHI）**：没有 use 的直接删除；只有一次 store 且支配全部 load 的，用存储值替换所有 load；只在一个块内使用的，每个 load 取它前面最近的 store 值。

* **插入 PHI 节点**：收集定义块，反向求 live-in，在用**裁剪过的迭代支配边界**给出的候选块里插入 PHI。

* **变量重命名 (Variable Renaming)**：PHI 就位后，沿支配树把内存访问改写成 SSA。
  1. **值栈初始化**：为每个 alloca 建立 SSA 值栈，以 `undef` 作为初始入口值。
  2. **遍历支配树与重命名**：进块时先把该块的新 PHI 入栈，再把 `load` 替换为栈顶值、把 `store` 的新值压栈。
  3. **传递数据给后继**：遍历 CFG 后继块，用当前栈顶值为后继块内的 PHI 填入出块值。
  4. **离开子树时回退**：回溯前弹出本块压入的全部定义，避免污染兄弟分支。

* **清理 alloca**：删除已无访问的 `alloca`。

* **折叠退化 PHI**：除自引用外入值全相同的 PHI 折叠成那个唯一值，入值全为自身的折叠成 `undef`。
